Getty 是用 Go 编写的异步网络 I/O 库，统一处理 TCP、UDP 和 WebSocket 会话。我的贡献主要围绕连接建立、重连和关闭之间的边界，避免异常处理本身再引发死锁、空指针或资源泄漏。

其中部分修复也提交到了 Apache 的 dubbo-getty 分支。这里按 Getty 仓库的实际改动说明，测试信息来自对应 PR。

## PR #140：理顺客户端重连与关闭的生命周期

已合并 · [原始 PR](https://github.com/AlexStocks/getty/pull/140) · [代码变更](https://github.com/AlexStocks/getty/pull/140/files)

### 背景

客户端通过连接池维持可用会话。连接失败、会话刚启动就关闭、多个会话同时断开，以及业务回调主动关闭客户端，都可能与重连过程交错。

### 问题

`connect()` 在新会话回调失败时存在不受上层预算约束的循环；重连属性在 `run()` 之后才设置，导致刚启动就断开的会话可能漏掉重连。与此同时，并发触发可能重复拨号，关闭客户端与会话入池竞争可能泄漏连接，在重连回调内调用 `Close()` 还可能形成等待自身退出的死锁。

### 解决方式

- 将 `connect()` 改为单次尝试并返回成功与否，由 `reConnect()` 统一负责失败计数和退避，成功后重置失败计数。
- 在启动会话前写入重连属性；若会话启动后客户端已经停止，则清理属性并关闭会话，防止泄漏或再次触发重连。
- 使用 `reconnectDone` 和 `reconnectPending` 合并同时到来的重连请求，使它们共用一个工作协程。
- 移除客户端关闭时对重连工作协程的等待，让工作协程观察关闭信号后自行退出，避免在回调里关闭客户端时等待自己。

### 成果

重试预算开始约束失败尝试，并发触发不会各自启动拨号流程。关闭客户端也不再依赖重连回调先返回。新增回归测试覆盖启动前属性设置、并发请求合并、退避期间触发、关闭后不再重连以及回调内关闭客户端等场景。

这一项同步了 dubbo-getty #142 的部分最终修复，但仍针对 Getty 的 `transport/` 目录和已有实现进行了适配。

## PR #99：关闭被拒绝的 WebSocket 自连接

已合并 · [原始 PR](https://github.com/AlexStocks/getty/pull/99) · [代码变更](https://github.com/AlexStocks/getty/pull/99/files)

### 背景

服务端在处理 WebSocket 请求时，先完成 HTTP 协议升级，再判断连接是否属于应拒绝的自连接。

### 问题

当协议升级成功后才识别出自连接，原来的拒绝分支直接返回。虽然没有创建业务会话，已经升级的底层连接却没有关闭，留下了资源泄漏路径。

### 解决方式

在拒绝自连接的分支主动关闭升级后的 WebSocket，再返回。回归测试真实走过升级流程，分别检查升级成功、不创建会话，以及连接在处理函数返回前已关闭。

### 成果

拒绝请求和释放连接形成了完整的处理路径。PR 记录了专门的 `TestWSServeWSRequestClosesSelfConnectConn`、全量 Go 测试和 `go vet` 验证，将这个此前遗漏的分支纳入回归保护。

## PR #98：避免空监听器让错误清理再次崩溃

已合并 · [原始 PR](https://github.com/AlexStocks/getty/pull/98) · [代码变更](https://github.com/AlexStocks/getty/pull/98/files)

### 背景

会话读包或解码失败后，`handlePackage` 会进入错误清理流程，通过监听器通知上层错误与关闭事件。

### 问题

原来的判断是 `s != nil || s.listener != nil`。当会话存在但监听器为空时，条件仍然成立，随后调用 `OnError` 就会发生空指针异常；即便修复这一处，紧接着的 `OnClose` 仍可能遇到相同问题。

### 解决方式

将调用 `OnError` 的条件改为会话和监听器同时存在，并为 `OnClose` 补上空值保护。新增回归测试，构造没有监听器的错误清理场景。

### 成果

读包错误能够沿清理流程收尾，不再因为通知一个不存在的监听器而发生第二次崩溃。修复同时覆盖错误回调和关闭回调，避免只消除第一个异常点。
